# V6.39 — Force Regional Member IDs

Why V6.37 appeared not to work:

- The React/Vercel deployment does not generate Membership IDs.
- Membership IDs are generated by Supabase database functions.
- V6.37 also intentionally preserved existing `BAP-MID-*` IDs.

V6.39 fixes both cases.

## Existing IDs

Existing IDs beginning with `BAP-MID-` are converted to:

`BAP-{REGION}-{YEAR}-{000001}`

Examples:
- `BAP-NCR-2026-000001`
- `BAP-CAR-2026-000001`
- `BAP-R3-2026-000001`
- `BAP-R5-2026-000001`

## Old QR compatibility

Before changing an old ID, V6.39 stores it as an alias.

The public profile RPC accepts:
- new regional Membership ID
- old BAP-MID Membership ID
- Control Number

Therefore previously printed QR/profile links using the old ID can still locate
the same member.

## Installation

On an existing database, run once:

`supabase/17_FORCE_REGIONAL_EXISTING_IDS.sql`

Then refresh the application.

No frontend change is required for the ID value because every ID/profile/
directory/export view already reads `members.member_id_number`.
