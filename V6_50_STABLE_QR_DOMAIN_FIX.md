# V6.50 — Stable QR Domain Fix

This release prevents newly generated member QR codes from using a temporary or deployment-specific Vercel URL.

## Changes
- QR generation now prefers `VITE_PUBLIC_SITE_URL`.
- If that variable is not configured, the app falls back to the stable project domain:
  `https://bap-membership-system-fresh-v3.vercel.app`
- Digital ID, public profile, certificate, directory, Master tools, and Excel-export QR codes continue to share the same member profile URL.
- Legacy route redirects from V6.49 remain included.

## Recommended Vercel variable
While the custom domain is still being fixed:

`VITE_PUBLIC_SITE_URL=https://bap-membership-system-fresh-v3.vercel.app`

After the custom domain is fully valid and opening correctly:

`VITE_PUBLIC_SITE_URL=https://www.bapofficial.com`

Redeploy Production after changing the variable.

## Important limitation for already printed QR codes
A QR code is static. If an already printed QR contains a deleted deployment-specific host such as
`https://<old-deployment-id>.vercel.app/...`, frontend code on the current project cannot intercept it because Vercel returns `DEPLOYMENT_NOT_FOUND` before this app runs.

Those old printed QRs can only be preserved if the exact encoded host can be restored/aliased to the current project. Otherwise, regenerate/reprint the QR. New QR codes generated by V6.50 will use the stable configured domain.
